# Living Island — Unity 6 (6000.6.0f1) URP graphics showcase

A walkable third-person tropical island with a 4-minute day/night cycle, five blended weather states with
lightning, a custom Gerstner-wave water shader with underwater view, GPU-instanced grass, wind-driven palms
modelled in Blender (through the Blender MCP), a campfire, a lighthouse, a bobbing rowboat, fireflies,
synthesized audio, a photo mode with 3840×2160 capture and live quality presets.
Everything is generated by code at runtime; the only authored assets are the Blender props in
`Assets/Models/*.glb` (built by a Python script, see "Blender props").

## How to open and run

1. Unity Hub → **Add** → select the folder `Living Island` (next to this README) → open with **Unity 6000.6.0f1**.
2. Press **Play**. Whatever scene is open, Play starts `Assets/Scenes/Island.unity`
   (`Assets/Editor/PlayModeStartScene.cs`). That scene contains a single object with `GameBootstrap`,
   which builds the whole game in ~1.3 s (black fade-in while shaders warm up) at **noon, clear weather,
   High quality, seed 777**, with the player on the bay beach looking at the water and palms.
3. Optional: menu **Living Island → Run Project Setup** re-applies the project configuration (it is idempotent
   and already applied). A Windows build can be made with `LivingIsland.EditorTools.BuildTools.BuildPlayer`
   (output `Build/LivingIsland.exe`).

## Architecture (which file does what)

`Assets/Scripts`

| Folder / file | Responsibility |
|---|---|
| `Config/GameConfig.cs` | **The one config file**: every number from the specification (seed 777, 512 samples, 500 m, 45 m peak, 60 m bay, waves, colours, counts, speeds, timings, presets...) plus derived tuning values. Shaders receive them through `Rendering/ShaderGlobals.cs`; the Blender script parses its "Blender props" block. |
| `Core/GameBootstrap.cs` | Builds camera, light, sky, weather, island, ocean, player, grass, FX, audio, post, quality, photo mode and UI; routes F1/F12/Esc/Tab/P/T; startup shader warm-up + fade-in; regenerate/restart/quit. |
| `Core/Game.cs`, `Core/GameInput.cs`, `Core/IslandAssets.cs`, `Core/MaterialLibrary.cs` | System registry; Input System wrapper (hotkeys disabled while typing); ScriptableObject in `Resources` referencing shaders + Blender prefabs; runtime materials. |
| `Terrain/IslandGenerator.cs` | Seeded height function: noisy radial coastline, beach/seabed profile (5.7° beach, −12 m floor), 6-octave fBm hills, ridged mountain rescaled to exactly 45 m, capsule-SDF bay (60 m), vertical cliff arc. |
| `Terrain/IslandData.cs`, `Noise2D.cs`, `DetRandom.cs` | Heightmap + exact triangle-interpolated height queries, normals, surface type, coastline distance; seeded gradient noise; deterministic SplitMix64 RNG. |
| `Terrain/IslandAnalysis.cs` | Measures peak, diameter, floor depth, bay width, cliff stretch/slope, beach slope (logged as evidence on every generation). |
| `Terrain/TerrainBuilder.cs` | The single 512×512-sample mesh, MeshCollider, GPU height texture. |
| `World/IslandWorld.cs`, `PoiPlanner.cs` | Seed → everything pipeline; picks lighthouse (cliff top), campfire (bay beach), rowboat (bay shallows), spawn; flattens pads. |
| `World/Lighthouse.cs`, `Campfire.cs`, `Rowboat.cs` | Rotating lamp + beam cone + spot light; fire/sparks/smoke + flickering shadowed light + rock ring + 3 log seats; wave-driven bobbing. |
| `Vegetation/PropPlacer.cs`, `PlacementValidator.cs`, `FoliageFactory.cs` | Deterministic placement of 300 palms, 150 rocks, 60 bushes, 20 flower patches; float/sink/water validation on the real meshes; procedural bush and flower meshes. |
| `Vegetation/GrassRenderer.cs` + `Shaders/GrassPlacement.compute` | GPU grass: compute placement around the camera every frame, `Graphics.RenderMeshIndirect`, async count read-back. |
| `Water/WaterSurface.cs`, `WaveModel.cs` | 400×400 camera-centred grid with distance-based spacing; CPU mirror of the Gerstner waves (swimming, boat, underwater detection). |
| `Sky/TimeOfDay.cs`, `Atmosphere.cs`, `SkyController.cs`, `ColorCurve.cs` | Clock + 20°-tilted sun/moon path + colour curves; combines time/weather/lightning into light, sky, ambient, fog, underwater state; skybox material, 1500-star table, procedural environment cubemap. |
| `Weather/WeatherSystem.cs`, `LightningSystem.cs`, `RainSystem.cs` | State machine with 8 s blends and auto mode; strikes, flash, procedural bolt, thunder scheduling; rain streaks + ground splashes. |
| `FX/FireflySystem.cs`, `SwimEffects.cs`, `ParticleFactory.cs` | Night fireflies within 40 m; swim splashes; ParticleSystem helpers. |
| `Player/PlayerController.cs`, `PlayerAvatar.cs`, `ThirdPersonCamera.cs` | Walk/run/jump/swim + world boundary; primitive humanoid with procedural walk/run/jump/swim animation; orbit camera with collision. |
| `Audio/AudioSynth.cs`, `AudioSystem.cs` | All sounds synthesized at startup (29 clips); mixing by shore distance, wind, weather, time; positional campfire; footsteps by surface; underwater low-pass. |
| `Rendering/PostFX.cs`, `QualityManager.cs`, `PhotoMode.cs`, `ScreenshotService.cs`, `ShaderGlobals.cs`, `ShaderIds.cs` | URP Volume + grading; live presets; photo camera + 4K capture; screenshots; config → shader globals. |
| `UI/*` | uGUI built in code: HUD (clock + procedural weather icon), F1 overlay, pause menu, settings panel, photo panel, procedural sprites/icons. |
| `Testing/AutoTest*.cs` | Automated self-check driver, active only with `-autotest <scenario>` on the command line. |

`Assets/Shaders` (hand-written HLSL on the URP 17.6 shader library; everything procedural, no textures):
`Terrain` (height/slope splat, triplanar rock, sand ripples, caustics), `Water` (Gerstner + all water effects),
`Sky` / `SkyCube` (sky dome / environment cubemap faces), `Grass` + `GrassPlacement.compute`, `Bark` / `Foliage`
(palms, bushes; vertex-colour wind, alpha-to-coverage leaves), `Rock`, `Prop` (night emission for windows/lamp),
`Glass`, `Flower`, `ParticleAdditive`, `ParticleAlpha`, `Rain`, `Beam`, `Lightning`; shared code in `Include/`
(`IslandCommon` lighting/fog/wetness/caustics, `IslandNoise`, `TerrainCommon`, `SkyCommon`, `VegetationWind`).

`Assets/Editor`: `GlbImporter.cs` + `MiniJson.cs` (own `.glb` importer), `ProjectSetup.cs` (URP/quality/layers/player
settings, asset registry, scene, build settings), `BuildTools.cs`, `PlayModeStartScene.cs`.
`Assets/Tests/PlayMode`: editor Play Mode smoke test. `Tools/`: `run_guarded.ps1` (GPU launch gate, monitoring, hard stop,
PID-tree timeout), `unity_batch.ps1`, `run_player.ps1`, `unity_playmode_test.ps1`, and `Blender/` (prop scripts).

## Blender props (Variant B, Blender MCP)

The connected Blender (5.2.2 LTS) had `Living Island/LivingIslandOpus5.5.blend` open (verified via `bpy.data.filepath`
before any change). All props were modelled with `bpy`/`bmesh` code through the MCP and saved into that file;
the re-runnable script is `Tools/Blender/build_island_props.py` (entry point; the code is split by responsibility into
`props_core.py`, `props_geometry.py`, `props_palms.py`, `props_rocks.py`, `props_lighthouse.py`, `props_boat_wood.py`,
`props_export.py` next to it) and reads its budgets from `GameConfig.cs`. To rebuild the props, run in the open Blender:
`exec(compile(open(p).read(), p, "exec"), {"__name__": "__main__"})` with `p` = the path of `build_island_props.py`.

| Asset | Triangles (budget) |
|---|---|
| `SM_Palm_01..03` (LOD0 / LOD1; 8 / 9 / 10 fronds, 32-ring curved tapering trunk, vertex-colour wind weights) | 1982 / 454, 2030 / 466, 1958 / 478 (3000 / 800) |
| `SM_Rock_01..05` (noise-displaced boulder, slab, tall, split, ledged) | 1250, 1150, 1300, 1350, 1300 (1500) |
| `SM_Lighthouse` (+ child `SM_Lighthouse_Lamp`, separate emissive `M_LH_Lamp`) — 18.0 m | 5916 + 320 (8000) |
| `SM_Rowboat` (clinker hull, bench, 2 oars, oarlocks) | 2026 (3000) |
| `SM_Driftwood` (log seats), `SM_CampfireLogs` | 903, 810 |

Export steps (done by the script, per asset): move the asset's root objects to the origin, select them,
`bpy.ops.export_scene.gltf(export_format='GLB', use_selection=True, export_yup=True, export_apply=True,
export_normals=True, export_texcoords=True, export_materials='EXPORT', export_image_format='NONE',
export_vertex_color='ACTIVE', export_cameras=False, export_lights=False, export_animations=False, ...)` into
`Assets/Models/<Name>.glb`, re-parse the GLB JSON to verify nodes/attributes/materials, restore the layout, save
the .blend. In Unity, `Assets/Editor/GlbImporter.cs` (a ScriptedImporter, no external package) imports each `.glb`
as a prefab: X-mirror + winding swap + V flip, one submesh per material, `COLOR_0` kept, `_LOD0/_LOD1` → LODGroup,
URP materials created with the project shaders chosen by material name (`M_PalmTrunk` → Bark, `M_PalmFrond` →
Foliage, `M_Rock` → Rock, `*Glass` → Glass, `M_LH_Window`/`M_LH_Lamp` → Prop with night emission, others → Prop).

## Decisions

- **Config**: every number given by the specification lives in `GameConfig.cs`; small look-tuning constants that the spec
  does not define (noise frequencies, albedo colours inside shaders, animation amplitudes) stay next to their code, commented.
- **Custom terrain mesh instead of Unity `Terrain`**: exactly 512×512 samples, one mesh, full shader control; the CPU
  height query reproduces the mesh triangles exactly, so placement and validation are exact.
- **Custom HLSL shaders for everything** (URP's PBR BRDF, main-light cascades, Forward+ additional lights incl.
  the campfire's point-light shadows, SSAO). Cascaded soft main-light shadows are fixed defines ("shadows always on").
  Unity fog is replaced by an analytic exponential height fog shared by every shader; underwater fog uses the same hook.
- **Reflections**: a procedural substitute for a reflection probe — a 128² HDR cubemap re-rendered from the sky shader
  every 0.5 s (follows time of day and weather) and used by all shaders and as the default reflection.
- **Grass** is placed on the GPU every frame on a world-anchored 0.14 m candidate grid around the camera (stable, no
  swimming), density falls with distance (full within 9 m, 5% at 80 m, nothing beyond 80 m), and a smoothed
  density scale steers the count to the preset budget (High 100,000 = "80k+", Medium 50,000, Low 20,000).
  The overlay shows blades actually drawn this frame (read back asynchronously).
- **Glb importer written in-house**: Unity 6.6 has no built-in glTF importer and the brief forbids downloads.
- **One directional light** is the sun by day and the moon (blue, 0.05) by night, swapped while both are ~0.
- **Weather numbers** not given by the spec were chosen: visibility Clear 6000 m, Cloudy 3000 m, Rain 700 m,
  Storm 400 m (Fog = 60 m as specified); Storm = wind ×3 and waves ×1.8 as specified. Keys 1–5 also turn auto mode off.
- **Shoreline**: waves are damped in water shallower than 3.5 m (same formula on GPU and CPU), and the water fades over
  its last 7 cm of depth, so the beach line has no seam or flicker; foam appears only where the depth is below 0.6 m.
- **Stars**: 1500 stars, all on the visible upper hemisphere (3.6°–78° elevation) so all 1500 can be seen at night;
  they slowly rotate, twinkle, are hidden by clouds and by thick fog.
- **Photo mode** pauses the day cycle (the time slider holds) and uses the right mouse button for looking so the
  sliders stay usable; the 4K capture uses `RenderPipeline.SubmitRenderRequest` into a 3840×2160 RenderTexture.
- **Night grading**: +1.15 EV and cooler colours at night so the 0.05-intensity moonlit scene stays readable.
- **Anti-aliasing**: MSAA 4× (High) / 2× (Medium) with alpha-to-coverage foliage; FXAA on Low.
- **URP post-processing variant stripping disabled** in the URP global settings, because the volume profile is built at
  runtime (otherwise builds strip the depth-of-field shader).
- **Testing**: `-autotest acceptance | showcase | keys | audio | hitch | perf | soak1..3` drives the real game (keyboard events
  are injected through the Input System for the hotkey test) and reports measurements, screenshots and every console
  warning/error; Tools scripts enforce the GPU safety rules for every Unity/player process.

## How it was verified

All checks ran on this PC through `Tools/` (one process at a time, GPU gate + monitoring + PID timeouts):
`Tools/unity_batch.ps1 -Method LivingIsland.EditorTools.BuildTools.BuildPlayer` builds `Build/LivingIsland.exe`;
`Tools/run_player.ps1 -GameArgs "-autotest <scenario>"` runs a scenario (≤ 115 s) and prints the `[LI] TEST` results
plus every warning/error-like line of the raw player log; `Tools/unity_playmode_test.ps1` runs the editor Play Mode
test. Logs are in `Living Island/Logs/`, the automated screenshots in `Living Island/Build/Screenshots/`
(A* = acceptance steps, B* = showcase shots, S* = soak runs). Results per requirement: see `CHECKLIST.md`.
Summary of the final runs: every scenario (acceptance, showcase, keys incl. Restart, audio, hitch, 3 soak sessions, perf) and the
editor Play Mode test (45 s, passed) reported 0 warnings and 0 errors; all 22 hotkey checks passed with real Input System events.

## Known limitations

- Draw-call/batch counters in the F1 overlay show "n/a" in release builds (Unity exposes them only in the editor and
  development builds); FPS, frame time, triangles and grass/particle/physics counts are always shown.
- Water reflects only the sky (procedural cubemap); there are no planar/screen-space reflections of the island.
- No split "half above/half below water" view: the camera switches between above- and underwater rendering and is kept
  out of a ±0.18 m band around the animated surface.
- The orbit camera always looks at the player; the underwater sea floor with caustics is best seen in photo mode or
  from the surface in shallow water.
- The grass count reaches the budget wherever enough grass exists within 80 m (93k–102k measured on High in the
  meadows and at the spawn beach); far out at sea it is lower because there is no grass to place.
- Palm trunk collision is a 3 m capsule at the base (the curved upper trunk does not collide).
- While the sun moves (1.5°/s at speed 1) shadow edges can crawl very slightly; 4096² cascades and high soft-shadow
  filtering keep it subtle.

## Performance on this PC (RTX 5070 12 GB, Ryzen 7 5700X3D, 64 GB)

Measured with the Windows build of this project (same scene/code as Play Mode), GPU sampled with `nvidia-smi`
every 5 s by `Tools/run_guarded.ps1` (log: `Living Island/Logs/gpu_monitor.csv`; VRAM is the whole GPU, including
other programs running on this shared PC).

| Measurement | Result |
|---|---|
| Benchmark run (`-autotest perf`), **2560×1440 borderless window, High preset, VSync off**, clear noon, camera slowly panning over the bay | **411.7 FPS average** (2.43 ms), 1% low 265.8 FPS (3.76 ms), 94,836 grass blades |
| Same run, **Storm at night** (6,500 rain particles, lightning) | **367.1 FPS average** (2.72 ms), 1% low 213.3 FPS (4.69 ms) |
| Normal play at 1920×1080, VSync on (180 Hz monitor), High | 176–178 FPS (VSync-limited) in the ~105 s soak sessions |
| Peak GPU temperature (all runs) | 68 °C (benchmark: 67 °C at ~250 W, 97–100 % utilisation) |
| Peak VRAM used on the GPU (all runs) | 2.88 GB of 12 GB (benchmark run: 2.13 GB) |
| Lowest free system RAM during runs | 40.3 GB |
| Startup to playable | ~1.2 s (island generation incl. placement 0.36–0.42 s; audio synthesis 0.5 s) |
| Regeneration with a new seed | 0.34–0.93 s (limit 5 s) |

The launch gate (VRAM ≤ 8.5 GB, ≤ 78 °C, ≥ 12 GB free RAM) passed on the first check for every run; no hard
stop was ever triggered. The only intentionally uncapped run was the single ≤ 60 s benchmark above (the 45 s editor test in
batch mode has no swap chain/VSync; it was monitored like every run and peaked at 45 °C).
